# カスタムマップ設計の独立レビュー記録

レビュー日: 2026-10-25。対象は [運用計画](escape-worlds-plan.md) と [Discord UX設計](escape-discord-ux.md)である。

レビュー後の表示名修正により、機能名は「カスタムマップ」、既存のPaper / Forge等の区分は「通常サーバー」に統一した。採用範囲、動作仕様、コマンド、内部IDはこの表記変更では変更しない。

ユーザーの依頼に基づき、初稿の作成完了後に、設計作成へ参加していない2つのサブエージェントが別々にレビューした。UX担当は初心者・スマートフォン・共同プレイの操作を、運用整合性担当は既存コードと設計間の状態・権限・データ・復旧を確認した。いずれも読み取りのみであり、本番操作とファイル編集は行っていない。修正は主担当が行った。

## 主担当の追加整合確認

- 下限150分・上限不明の作品を「120分以内、未記載も含む」で返さないよう、既知の値に反する候補は除外する規則を追加した。
- 期限切れの検索ボタンに依存せず、ホームから前回条件を再表示する経路を明記した。
- 運用計画に残っていた特殊ローダー向けの構成表記を初期Vanilla限定へ揃えた。
- 実装時の受入シナリオへ、ID未承認、辞退、完了取消し、未クリア消去、公開範囲、共有先消失、保守リース、再開ポート変更、容量不足を追加した。

## 最新Discord仕様を踏まえた追加レビュー

前回の再確認完了後、ユーザーの追加依頼に基づいてDiscord公式仕様、SDK 2.7.1のAPI・公開wheel、PyPIを確認し、[プラットフォーム適用設計](escape-discord-platform.md)を追加した。Components V2、Label付き検索Modal、常設パネル、実行可能な `/escape home`、本人用と共有の応答を設計へ反映した。前回の合格判定は、この新しい表示方式を確認したものとして流用していない。

両サブエージェントへ追加レビューを依頼し、UX担当2件・技術整合性担当3件を受領した。

| ID / 重要度 | 指摘 | 反映した修正 |
| --- | --- | --- |
| V01 / P2 | プリセット時間と任意時間を別に保持すると、解除時に以前の上限が復活する。 | 単一のmax_minutesに統一した。空欄・時間上限解除はnullとし、現在の任意値を基本Selectへ追加する。 |
| V02 / P2 | コマンドで指定した17人等の人数が固定Selectになく、フォーム再表示で消える。 | 標準候補にない現在値を一時候補として追加し、25候補以内で保持する。 |
| V03 / P1 | Modal送信後のdeferが既定thinking=Falseだと、共有パネルへ個人の検索結果を描画する経路になる。 | 初回・共有起点の個人応答はdefer(ephemeral=True, thinking=True)に固定し、type 6 / 7は照合済みの本人用画面に限定する。 |
| V04 / P2 | LayoutViewの既定180秒と、ephemeralの15分補正が混同されている。 | 個人画面はtimeout=900を明示し、トークン・無操作期限・DB上の画面期限・保存条件の寿命を分けた。 |
| V05 / P2 | 旧仕様にあるMinecraft版の絞り込みが、新しい5項目フォームから抜けている。 | 結果画面の「環境条件」から別Modalを開く。6個目のLabelやModalの直接連鎖を使わない。操作群を分けてV2総数を再計算した。 |

5件を設計と受入条件へ反映し、修正版を両担当へ再提示した。UX担当は2件の解消と環境条件の動線を、技術整合性担当は3件の解消、30 / 24要素の計算、単一の時間条件と現在値保持を再確認した。両担当とも今回の範囲で未解消の重大な不整合は見つからなかった。

文書のリンク・構造・文字化け・空白と、設計した要素数を検査した。APIへの送信、Discordの端末ごとの表示・操作、実マップ試験は未実施である。
