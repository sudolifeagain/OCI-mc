## 並列動作と復元

- カスタムマップ2本で各4人、合計8人の同時接続を確認した。計測時RSSは約0.7～0.8GiB、ホストの空きメモリは約15GiBであった。
- Paperの複製とカスタムマップでも各4人の同時接続を確認した。Paperの100tickサンプルは平均20.5ms、P95は45.0ms、P99は187.3msであった。
- Paper併用中にForge起動と3台目の起動を拒否した。
- セッション単位のバックアップから別IDへ復元し、元の保存データを保持した。永続DBと起動記録から新しいサービスインスタンスで復帰し、4人の再接続を確認した。
- クリア申告の取り消し、ごみ箱への移動、取り消し、完全消去を複製で確認した。Notionの名前による完全一致取得は本番APIで確認した。

## 接続先の確定

新設ポート25568・25569はOCI側の到達性確認で遮断された。利用者の承認により、開放済みの25566・25567をForge系と排他共有する。25566は稼働中のForge、25567は一時的なTCP疎通用リスナーにより、作業PCからの外部到達を確認した。ポート共有時の保守再起動は専用RCONの応答で稼働対象を識別する。

## 制約

描画・音声・リソースパックの見え方・謎解きの完走・長時間の実プレイヤー試遊は確認対象に含めない。Paper併用の合成クライアントでは一部に通信タイムアウトがあり、全クライアントの継続接続を保証する負荷試験ではない。初期の運用人数は作者の対応範囲内の2～4人とし、同時実行は2プロセスに制限する。

Discordのネイティブ画面操作ツールは「failed to write kernel assets」で起動できなかった。SDKのシリアライズとDiscord APIでのメッセージ受理・コマンド登録を本番反映時に確認する。
