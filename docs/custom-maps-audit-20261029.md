# 脱出マップの権限・データパック監査（2026年10月29日）

公開60作品を確認し、8作品のOP設定と10作品の配布データ不備を修正した。英雄墓地Remakeの既存修復も再検証した。修正後の15作品は、作者指定版のサーバーで読み込みエラーなし・合成クライアントの接続成功・想定OPレベルとの一致を確認した。作品別の集計は [JSON証跡](custom-maps-audit-20261029.json) に記録している。

本変更はPRとして提示するものであり、本番への反映は行っていない。

## 権限の修正

本・チャットの `run_command` はプレイヤーの権限で実行される。原本の関数・コマンドブロック・コンテナ内の本を走査し、次の8作品を `op_required: true` に変更した。許可済みプレイヤーにレベル2を付与する既存処理を、新規起動・再開・参加者追加に使用する。同じID・改訂・Minecraft版にだけカタログの修正が優先される。

| ID | 作品 | 確認した操作 |
| --- | --- | --- |
| deep-sea | 深海からの脱出 | 本のクリックコマンド |
| summer-courage | 夏の肝試し | 本・チャットのクリックコマンド |
| lost-melodia | 喪失メロディア | 本・チャットのクリックコマンド |
| forgotten-museum | 現世忘れの美術館 | 本・チャットのクリックコマンド |
| library | その謎解きは貸出中です。 | 本・チャットのクリックコマンド |
| llama | ほくそ笑むリャマ | 本・チャットのクリックコマンド |
| moonlight-flower | 月光に咲く魔法の花 | 開発者ワープ本のクリックコマンド |
| seventh-period-shrine | 七限目は祠の中で | 本・チャットのクリックコマンド |

看板のクリックは看板側の権限で動作するため、プレイヤーOPの根拠から除外した。看板を渡すコマンドも同様である。`trigger` など一般プレイヤーが使用できるコマンドだけの作品にもOPを追加していない。

## データパックの修復

`infra/custom-map-resource-fixes.json` の既知内容にだけ適用する。Minecraft版・識別関数・対象ファイルまたはフォルダー全体のSHA-256を照合し、起動枠の複製だけを修復する。退避・変更前の内容は `.resource-fixes/` に保存する。原本、保存スコア、攻略状態を変更しない。未知の編集がある対象は修復前に停止する。

| ID | 原本の読み込みエラー行数 | 修復 |
| --- | ---: | --- |
| forbidden-abyss | 39 | 大文字の作業用名前空間と空の述語・進捗JSONを退避 |
| llama | 208 | 日本語名のバックアップ関数フォルダー2件とメモ2件を退避 |
| lost-melodia | 4 | 未実装イベント3件の説明文をコメント化し、参照のない未完成関数を退避 |
| forgotten-museum | 9 | 空JSON8件を退避し、無効化する標準進捗・地図拡張レシピをpack filterで指定 |
| balloon-village | 1 | カスタムレシピ進捗の、存在しない標準親進捗への参照を除去 |
| no-entrance | 1 | 関数フォルダー内のReadMe.mdを退避 |

空JSONによる標準コンテンツの無効化は、対象IDを明示したpack filterに置き換えて意図を維持した。エラー行数は連鎖エラーを含むため、独立した不具合件数ではない。英雄墓地Remakeは原本で3行、既存の12操作を適用した複製で0行であった。上表の10作品も修復後はすべて0行である。

## 検証と今後の受入条件

- 60作品の原本を静的走査し、リージョンの読み取り失敗は0件であった。旧形式のNBT・data/functionsと26.xの名前空間付きディメンション、旧・新形式の本に対応する。
- 60作品で指定版のVanillaサーバー起動と接続を確認した。39作品は全ワールドの複製、21作品は原本データパックとlevel.datまたは平坦生成設定を使用したローダー検査である。
- 修正対象および英雄墓地Remakeの15作品は、全ワールドの複製で再検証した。OPが必要な作品はレベル2、不要な作品はレベル0をクライアント受信パケットから確認した。
- 通常の検証クライアントでも、libraryの2人にレベル2、forbidden-abyssの2人にレベル0が届くことを確認した。
- 最終11規則を60作品のデータパック複製に適用し、対象外への変更が0件、2回目の適用が全作品0件であることを確認した。実機検査の前後で原本level.datは不変であった。
- 単体テスト187件は失敗0件（Windowsのシンボリックリンク検査1件を除外）、ruffと公開リポジトリの秘密情報検査も成功した。

`verify_custom_maps.py` は初回・再開の両方で読み込みログ、プレイヤー操作の権限要件、接続クライアントのOPレベルを検証する。`custom_map_admin.py verify` も両回の証跡が不足していれば公開用の検証済み状態へ昇格させない。従来の接続成功・保存復元だけの証跡では不十分である。

今回の監査では保存・再開の実機試験をやり直していない。保存復元の既存証跡は従来の検証記録を参照する。描画・音声・謎解き完走・長時間の試遊も対象外である。
