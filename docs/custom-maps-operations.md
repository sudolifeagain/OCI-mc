# カスタムマップの運用

カスタムマップは通常サーバーと独立した保存データを持つ。Discordの `/escape home` または常設パネルを入口とし、マップ検索、参加準備、初期化、保存停止、再開、クリア申告、消去を操作する。

`DISCORD_CUSTOM_MAP_CHANNEL_ID` に専用の操作チャンネルを設定する。設定後は `/escape` と共有カードの操作・投稿をそのチャンネルに限定し、別の場所では移動先を個人向けに案内する。募集と履歴は専用チャンネルに集約する。通常の参加状況にはPaper・Forge系だけを表示する。`DISCORD_CUSTOM_MAP_LOG_CHANNEL_ID` は管理者向けのログチャンネルであり、通常サーバーの投稿先へフォールバックしない。Discord IDは `.env` に保存する。

## 参加とプレイ

1. 「マップを探す」で人数・難易度・時間・配布元・版・指定パック・このチャンネルの履歴を絞り込む。人気順は2026年10月25日に確認した配布元の通算順である。未知の値は推定せず、並べ替えでは後ろに置く。
2. 詳細から参加準備ルームを作る。共有カードが投稿されたチャンネルを閲覧できる利用者が参加する。
3. 通常サーバーのホワイトリストに載っているJava版のプレイヤーは追加登録なしで参加できる。Discord名とMinecraft名の紐付けや管理者承認は行わない。新しいプレイヤーは既存の `/whitelist_add` のサーバーで「カスタムマップ」を選んで追加する。追加できる役職は従来のコマンド設定に従う。
4. 各自が指定版・必要なパックを準備し、PCの種類と確認項目を設定する。確認項目は案内用であり、PCの自動検査は行わない。リンクは公式Launcherと作者の配布元へ向ける。
5. 代表者が「ワールドを起動」で原本から独立した複製を作り、RCONで応答を確認してから接続先を表示する。他の参加者のDiscord登録や準備確認を待たずに先に起動できる。作者指定の人数はゲーム内で遊ぶ際の条件であり、参加予定人数とサーバーの定員に反映する。起動結果は操作した人への案内と共有カードの両方を更新する。
6. 「保存して中断」で正常保存・停止を確認して枠を空ける。「続きから」は同じ保存データの再開準備を開く。今回の参加者と接続ポートを再確認する。
7. 「クリアして終了」は手動申告である。自動的な攻略判定は行わない。終了後は別のマップを検索できる。

履歴はRCONで実接続を観測したワールドについて、募集したチャンネルに記録する。「最近のプレイ」と検索の履歴条件は現在のチャンネルを対象とし、個人の履歴には関連付けない。監視間隔は20秒である。共有カード・履歴・接続先は元のチャンネルの閲覧権限を再確認して表示する。開始・中断・消去では古い画面の世代を検査する。

起動・再開時に通常サーバーの `whitelist.json` と `/opt/minecraft/custom-maps/whitelist.json` をUUIDで統合する。通常サーバーのファイルは変更しない。カスタムマップ用の追加は停止中にも保存でき、稼働中のカスタムマップにはRCONで反映する。通常サーバー側で追加した名前は次の起動・再開時に取り込む。オンライン認証とホワイトリストは常に有効である。作者がOPを必要とするマップだけ、許可済みプレイヤーにレベル2の権限を付ける。

## 保存と復元

中断データは `/opt/minecraft/custom-maps/sessions/<session_id>/server` に保存する。原本は `templates/<map_id>/<revision>/world` に保持し、プレイによって変更しない。

「バックアップ・復元」または `/escape backups session_id:` から作成できる。プレイ中は正常停止してアーカイブを作り、同じ枠で復帰する。バックアップにはセッションの条件・ホワイトリスト・進行データを含め、RCON秘密値を含めない。遠隔保存は既存のNotion連携を使用する。遠隔保存済みのローカルZIPはセッションごとに直近3件を保持し、古いものは復元時にNotionから名前の完全一致で取得する。未アップロードのZIPは自動消去しない。定期バックアップもセッション単位で行い、中断・完了データに正常保存後の変更がない場合は重複作成しない。

復元は元の回を上書きせず、新しいIDの中断データを作る。SHA-256、元セッションID、マップID、原本改訂を検証する。通常サーバーの `/rollback` はカスタムマップへ使用できない。

Notionの遠隔保存直後は一覧への反映に時間がかかる場合がある。ローカルZIPも失われた状態で遠隔バックアップが見つからない場合は、少し待って復元を再試行する。

消去は7日間のごみ箱へ移動する。`/escape undo session_id:` またはカードの取り消し操作で戻せる。ごみ箱への移動では空き容量は増えない。プレイ名の確認と明示的な指定で完全消去できる。保持期限後は定期処理がごみ箱のデータを削除し、履歴は残す。

## 障害時の操作

Bot再起動時は枠内の起動記録とセッションIDを照合する。RUNNINGの回だけを自動復帰する。初期化・保存・消去の途中で止まった回や異常終了は、保存データを保持して確認待ちにする。再開データが欠落しても原本で作り直さない。

管理者の `/escape recover session_id:` は停止済みの失敗データを保全して中断状態へ戻す。異常終了後の進行は再開前に確認する。チャンネルが失われた場合は `channel:` に復旧先を明示する。共有範囲を広げる操作であるため、元の参加者が利用できる非公開チャンネルを選ぶ。

## 導入と拡張

Ansibleは2つの専用ユーザー、限定sudo、保存領域、Java 8、RCON秘密値、ホストの通信規則を準備する。Java 17・21・25は既存構成を利用する。旧版は[Mojang公式の対策](https://www.minecraft.net/en-us/article/important-message--security-vulnerability-java-edition)に従う。1.16.5以前は固定ハッシュの公式ログ設定を使用し、1.17系は起動引数でメッセージのlookupを無効にする。公開接続先は `.env` の `CUSTOM_MAP_PUBLIC_ADDRESS` に設定する。ゲーム接続はOCI側で開放済みのTCP 25566・25567をForge系と排他共有する。RCON 25578・25579は外部へ許可しない。Forgeを停止して復帰予約を解除してからカスタムマップを開始する。Paperとの併用は可能である。

`custom-maps.json` に出典付きの条件と正確な版・改訂を追加し、次のコマンドで原本を登録する。

```bash
cd /opt/minecraft/bot
./venv/bin/python scripts/custom_map_admin.py fetch --map MAP_ID
# 原本ZIPを指定する場合
./venv/bin/python scripts/custom_map_admin.py import --map MAP_ID --archive /private/map.zip
./venv/bin/python scripts/custom_map_admin.py inventory
```

複数ワールドを含むZIPは `--world-path` で採用する位置を指定する。登録済みの同じ改訂は上書きできない。更新は改訂を追加し、既存セッションには固定済みの条件を使う。

導入だけでは検索に表示しない。保守時間に `verify_custom_maps.py` で複製の複数人接続・正常停止・保存スコアの復元・原本の不変を確認して公開する。接続人数は作品の対応範囲内で最大4人とし、2人専用・上限3人の作品にはその上限を用いる。検証用クライアントは固定版の `minecraft-protocol` を使用し、127.0.0.1にだけ接続する。検証用複製だけがオフライン認証であり、通常のプレイは常にオンライン認証とホワイトリストを使用する。描画・音声・謎解き完走は実プレイヤーによる確認対象である。

`verify_custom_maps.py --catalog /private/candidates.json` で検証用カタログを指定できる。本番の公開カタログを変更せず、導入済みの新規候補だけを検証する。`--parallel` は `deep-sea` と `black-cat`、`--integration` は `karakurari` も含むカタログを必要とする。未検証候補は本番検索へ公開しない。対応版が24種類を超える場合、Discordの版検索は候補切り捨てを避けるためテキスト入力に切り替わる。空欄で版指定を解除できる。

受入検証では初回と再開の両方で、データパックの読み込みエラーがないこと、本・チャットのクリックコマンドに必要なOP設定、実クライアントへ通知されたOPレベルを確認する。`custom_map_admin.py verify --evidence` による昇格にも同じ証跡を必要とする。旧形式の接続・保存復元だけの証跡は使用できない。

原本を変更しない静的監査は次のコマンドで行う。全公開作品を対象とし、`--map MAP_ID` を繰り返すと対象を限定できる。読み取りエラーがある場合は監査未完了として扱い、指定版のMinecraftでの起動検査も併用する。

```bash
./venv/bin/python scripts/audit_custom_map_content.py --output /private/content-audit.json
```

Forge・Forge Altは他のMinecraftサーバーと排他である。保守や復帰予約も起動枠とメモリ予約に含める。通常サーバーとカスタムマップを合計2プロセスまでとし、カスタムマップは各ヒープ上限2GiB・プロセス予約3GiBに設定する。保存済みの中断データは起動枠を使わない。

## 配布データの既知不具合

英雄墓地Remakeは、魔法書・ヒントブックのリンクから関数を実行するため、ホワイトリスト内の利用者にレベル2のOPを設定する。同一のマップID・改訂・Minecraft版に限り、カタログの `op_required` を原本メタデータや保存済みセッションより優先する。新規作成、再開、参加者追加へ適用し、固定済みの版・リソースパックは維持する。

`infra/custom-map-resource-fixes.json` は既知の配布データ不備を修復する。起動ランチャーが版・識別ファイル・対象のSHA-256を照合し、起動枠内の複製だけへ適用する。フォルダーの退避は配下全ファイルのハッシュ一覧またはその一覧のSHA-256と照合する。原本と攻略の進行データは変更しない。未知の内容に変わっている場合は修復前に停止する。[2026年10月29日の60作品監査](custom-maps-audit-20261029.md)に、OP設定8作品、追加修復10作品と残るワールド診断を記録している。

日本語名の作業用関数2件と未使用フォルダーは、起動枠の `.resource-fixes/` へ退避する。変更する関数とメタデータも同じ場所へ退避する。ヒント39・40・51・52は既存の2ページと終了処理を保持し、存在しない3ページ目の予約だけを除去する。未定義のヒント69・70への未使用の分岐も除去する。

互換データパックは、重力部屋に残る旧 `gravityroom:gravity90`・`gravity180`・`gravity270` の重複呼び出しだけを無効化する。各座標のコマンド文字列が既知の旧値と一致する場合だけ変更する。現在の回転処理は座標8・11 / 13 / 13～16の制御部から `gravity:rotating_room/*` を呼ぶため、変更しない。
