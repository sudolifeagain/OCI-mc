# Forgeクライアントの互換構成

以下は初回Hybrid構成の検証記録である。現行候補の起動時修復・更新版・残す独自修正は[起動時修復](forge-startup-cleanup.md)を参照する。

Minecraft 1.20.1 / Forge 47.4.28を維持し、クライアント独自のクラス修正を4本から2本に減らす構成である。既存のJSONデータ修復57 jar・942リソースは維持する。

| 対象 | 採用構成 | サーバーへの影響 |
| --- | --- | --- |
| TFMG 1.0.2f | 独自クラス修正を撤去し、配布版TFMG Optimizerを追加 | 同じ補助MODを追加する。油田生成の共通Mixinがあり、新規生成の処理が変わる。既存ブロックの登録変更はない |
| JEI 15.20.0.129 | 元の配布jarへ戻す | 変更なし。5秒の遅延通知を維持する |
| BCLib 20.0.6 | クライアントのレジストリ参照修正を維持 | サーバーjarは変更しない |
| Supplementaries 1.20-3.1.42 | クライアントの袋16色のレシピ修正を維持 | サーバーjarは変更しない |
| PowerGrid 0.5.1 | 配布jarとWindowsランタイムDLL 3本 | 変更なし |
| Epic Fight 20.14.9 | 配布jarとクライアントのコスメ同期無効設定 | 変更なし |

Optimizerは[CurseForge file 8007822](https://www.curseforge.com/minecraft/mc-mods/tfmg-lag-fix/files/8007822)の配布物である。リリース名は1.0.2、jar内バージョンは1.0.0、元のファイル名はtfmg_patch.jarである。取得先とSHA-256はAnsibleのタスクで固定する。

TFMG本体のクラスは配布版へ戻すが、空の硫酸バケツタグを有効なJSONへ直す既存データ修復は維持する。「独自クラス修正2本」はこのデータ修復を含む数ではない。

## 更新を見送るバージョン

BCLib 20.0.16、BetterEnd 20.0.13、BetterNether 20.0.13の組み合わせは、専用サーバーのクライアント相当の状態でハンマーの引数なし取得が0件となった。Supplementaries 3.1.44とMoonlight 2.16.37も、サーバーデータ再読み込み前の色対応の欠落が残る。これらは今回のクライアント修正の代替とならず、新規コンテンツとワールド生成変更も含むため採用しない。

## 検証と復旧

候補の534 jar構成を隔離した実クライアントで起動し、ワールド・JEIの初期化、サーバーのグローバルレジストリがない状態のハンマー取得、クライアント標準状態の袋16色、TFMGのエンティティ・ブロック描画、PowerGridを確認する。検証用agentはゲームAPIを呼ぶだけであり、MODクラスの書き換えは行わない。

2026-10-23の実行では13項目が成功した。サーバーのグローバル登録情報を一時的に外してもハンマー9件、クライアント標準状態で袋レシピ16色を取得した。TFMGのエンティティ・ブロック双方の描画が成功し、描画後の視点情報も保持された。PowerGridのネイティブ機能が有効であり、JEIの監視間隔は配布版の5000ミリ秒であった。検証用クライアントは正常終了した。

本番変更はデプロイと同じ稼働状態保存・RCON正常終了・ボット停止・ボット起動の順序を使用する。Notionのワールドバックアップに加え、変更前のワールド・MOD・設定を別途退避する。サーバーの起動完了、RCON、MOD集合のハッシュを確認する。認証済みマルチプレイの画面操作は利用者が行い、その後にログを確認する。

問題発生時は正常終了後に追加したtfmg_patch-1.0.2.jarを外し、server-artifacts.jsonとAnsibleの対応変更を戻してからボット経由で再起動する。ワールドの復元が必要な場合は更新直前の退避、またはNotionのバックアップを使用する。
